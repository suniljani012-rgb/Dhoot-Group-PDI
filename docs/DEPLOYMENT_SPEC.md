## 1. ENVIRONMENT MODEL

| Environment | Purpose | Database | Auth | R2 Bucket | Worker |
|-------------|---------|----------|------|-----------|--------|
| local | Developer machine | Local Supabase | Local Supabase | Local (emulated) | Wrangler dev |
| development | Shared integration | Dev Supabase project | Dev Supabase | Dev R2 bucket | Dev Worker |
| staging | Pre-production | Staging Supabase | Staging Supabase | Staging R2 | Staging Worker |
| production | Live | Prod Supabase | Prod Supabase | Prod R2 | Prod Worker |

Environments are FULLY ISOLATED. No shared secrets, databases, or buckets.

---

## 2. HOSTING ARCHITECTURE

### 2.1 Web Application
- Platform: Cloudflare Pages
- Build: Vite → static output → Cloudflare Pages deploy
- Edge caching: Cloudflare handles static asset caching (versioned assets: 1-year cache)
- Custom domain: Configured in Cloudflare DNS

### 2.2 API Worker
- Platform: Cloudflare Workers
- Deploy via: `wrangler deploy` with environment flag
- Configuration: `wrangler.toml` (non-secret values only)
- Secrets: Cloudflare Secrets (never in source code)

### 2.3 Database
- Platform: Supabase (hosted PostgreSQL)
- Migrations: Applied via Supabase CLI or CI pipeline
- Connection: Worker uses Supabase connection string (stored as Cloudflare Secret)

### 2.4 Media Storage
- Platform: Cloudflare R2
- Buckets: private, per environment
- Access: presigned URLs only, generated by Worker

## 3. CI/CD PIPELINES

### 3.1 CI Pipeline (Every PR)

```
Trigger: Pull Request to develop or main

Steps:
1. Install dependencies (pnpm install --frozen-lockfile)
2. TypeScript typecheck (tsc --noEmit for all packages)
3. Lint (Biome check)
4. Unit tests (Vitest)
5. Integration tests (against dev DB)
6. Build (all apps and packages)
7. Migration validation
8. Dependency audit (pnpm audit)
9. Secret scan (TruffleHog or equivalent)

Failure: PR blocked from merge
```

### 3.2 Security Pipeline

```
Trigger: PR + Nightly schedule

Steps:
1. Dependency audit
2. Secret scan
3. SAST (CodeQL or equivalent)
4. Lockfile validation
5. License compliance check
```

### 3.3 Web Deploy Pipeline

```
Trigger: Merge to main (production) / develop (staging)

Steps:
1. Run CI pipeline (must pass)
2. Build web app
3. Deploy to Cloudflare Pages (environment-specific)
4. Smoke test (health check endpoint)
5. Notify team
```

### 3.4 Worker Deploy Pipeline

```
Trigger: Merge to main (production) / develop (staging)

Steps:
1. Run CI pipeline (must pass)
2. Build Worker
3. wrangler deploy --env [environment]
4. Verify Worker health endpoint
5. Notify team
```

### 3.5 Database Pipeline

```
Trigger: PRs containing migration files

Steps:
1. Validate migration file naming convention
2. Run migrations against test DB
3. Run RLS policy tests
4. Validate schema integrity
5. Block PR if migration fails
```

## 4. SECRET MANAGEMENT

All secrets stored in Cloudflare Secrets (per environment):

| Secret Name | Description |
|------------|-------------|
| SUPABASE_URL | Supabase project URL |
| SUPABASE_SERVICE_ROLE_KEY | Service role key (Worker only) |
| SUPABASE_JWT_SECRET | JWT verification secret |
| R2_ACCOUNT_ID | Cloudflare account ID |
| R2_ACCESS_KEY_ID | R2 credentials |
| R2_SECRET_ACCESS_KEY | R2 credentials |
| NOTIFICATION_API_KEY | Push notification service key |
| APP_SIGNING_SECRET | Application-level signing |

Secret rotation:
- Rotate on personnel change
- Rotate on suspected compromise immediately
- Rotation procedure documented and tested in staging first

## 5. MOBILE DEPLOYMENT

### 5.1 iOS
- Build: Expo Application Services (EAS Build)
- Distribution: TestFlight (staging) → App Store (production)
- OTA updates: Expo Updates for JS-only changes
- Native changes: full EAS build + store submission

### 5.2 Android
- Build: EAS Build
- Distribution: Internal track (staging) → Production track (production)
- OTA updates: Expo Updates for JS-only changes

### 5.3 Mobile Build Pipeline

```
Trigger: Tagged release

Steps:
1. Run CI (must pass)
2. EAS Build (iOS + Android)
3. Submit to TestFlight / Internal Track
4. QA sign-off on staging build
5. Submit to App Store / Production Track
```

## 6. RELEASE PROCESS

```
Feature branch
   → CI passes
   → Review + approval
   → Merge to develop
   → Staging deploy
   → QA testing
   → Smoke test
   → Approved
   → Merge to main
   → Production deploy
   → Monitor (30 min observation)
   → Confirm or rollback
```

Every release includes:
- CHANGELOG entry
- Migration (if applicable)
- Rollback plan documented
- Known issues noted

## 7. ROLLBACK PLAN

### Worker Rollback
- Previous Worker version retained in Cloudflare
- Rollback via `wrangler rollback` or re-deploy previous tag
- Execution time: < 2 minutes

### Web Rollback
- Previous Cloudflare Pages deployment retained
- Rollback via Cloudflare Pages dashboard or re-deploy previous tag
- Execution time: < 2 minutes

### Database Rollback
- Migrations are forward-only in production by default
- Rollback migration scripted and tested before production deploy where schema changes are involved
- Data rollback via Supabase point-in-time recovery (see DISASTER_RECOVERY.md)
